# CodeTV Implementation Guide

Technical reference for maintaining and extending CodeTV. Each section explains what a part does and **why** it is designed that way. For the user-facing manual (in Spanish), see [../manual-usuario.md](../manual-usuario.md). The Spanish technical document is [../arquitectura.md](../arquitectura.md).

## 1. Overview

CodeTV is a packaged web app for LG webOS TVs. It has three parts:

- **Interface** (`app/`): plain HTML, CSS and browser JavaScript, without frameworks. It runs in the Chromium engine of the TV.
- **Drive module** (`src/`, compiled to `app/js/app.js`): signs the service-account token and queries Google Drive. It is built as a classic script with esbuild.
- **Proxy** (`server/`): runs on a computer on the local network. It serves Drive content to the TV's `<video>` element, adding the authorization header.

```
TV (webOS)                                   Computer (local network)
┌──────────────────────────────┐             ┌───────────────────────┐
│ app/index.html               │             │ server/proxy.mjs      │
│  shell.js  screens.js        │  /stream/   │  Range, faststart,    │──► Google Drive
│  player.js music.js tracks.js│ ──────────► │  subtitles (WebVTT)   │   (Authorization)
│  drive.js  logic.js store.js │             └───────────────────────┘
│  errors.js nav.js icons.js   │
│  js/app.js (compiled src/)   │── listing and thumbnails ──────────────► Google Drive
└──────────────────────────────┘
```

## 2. Folder structure

| Path | Contents |
|---|---|
| `app/` | The interface. Packaged with `ares-package`. |
| `app/index.html` | Markup for every screen and the player. Script order matters. |

## 3. Interface modules

Load order in `index.html`: `flags.js`, `nav.js`, `icons.js`, `logic.js`, `store.js`, `errors.js`, `drive.js`, `player.js`, `tracks.js`, `music.js`, `themes.js`, `screens.js`, `shell.js`, then `js/service-account.js` and `js/app.js`.

Every module is an IIFE that attaches its API to `window` (`CodeXxx`). **Why:** the TV's browser does not support ES modules, and each part exposes only its own API.

| Module | Responsibility | Why it exists |
|---|---|---|
| `flags.js` | Feature switches (`videoSection`). | Disable a section without deleting its code. |
| `nav.js` | Arrow navigation by spatial proximity, and Enter. | Arrows must go to the nearest visible element, not the next one in the DOM. |
| `icons.js` | Stroke SVG icons with a size parameter. | One place for the icon style. |
| `logic.js` | Pure functions: sorting, progress, times, folders and queues. | No DOM or network, so they can be tested with `node --test`. |
| `store.js` | Reads and writes `localStorage` with the `codetv.` prefix. | If storage fails, the app keeps working without saving. |
| `errors.js` | Error log, classification and sanitizing of technical details. | An error with an explanation and an action is more useful than a raw message. |
| `drive.js` | Library access for the screens: roots, children, crawl, thumbnails and media URLs. | Centralizes caching and waiting for the compiled module. |
| `player.js` | The single player (`CodePlayer`): one `<video>`, states and progress. | One element avoids two audio sources and two positions. |
| `tracks.js` | Audio and subtitle panel. | Isolated: it only depends on `video.audioTracks` and `textTracks`. |
| `music.js` | Music player with its own `<audio>` element. | Independent of video; paused when a video starts. |
| `themes.js` | Color themes. **Generated** from `src/styles/tokens.css`. | Colors live in tokens, not in each screen's CSS. |
| `screens.js` | Content of Home, Explore, Video (disabled), Music, Photos and Settings. | Each screen is drawn when it is entered. |
| `shell.js` | Top bar, mini player, full view, controls, speeds, Back and the queue. | The only module that decides how the player is shown. |

### 3.1 One source of truth for playback

`CodePlayer` (in `player.js`) owns the `<video>` element. The element **never changes parent**: full view and mini only change its position and size inside `#stage`. **Why:** moving a `<video>` in the DOM restarts playback in many browsers.

State (`idle`, `playing`, `paused`, `ended`) and mode (`full`, `mini`) live in `CodePlayer`. `shell.js` subscribes and applies them in `render(s)`.

### 3.2 Screens and focus

`screens.js` builds elements and links them with `card()` or `row()`. Each item is an `<a href="#">`, with `data-id` when focus must be restored. **Why:** the remote can only focus links; an `<a>` receives focus and OK without extra code.

Long lists (Music, Photos) are drawn in chunks of 60 (`lazyList`). When the user scrolls near the end or focuses one of the last items, the next chunk is appended. **Why:** drawing thousands of cards with thumbnails blocks the TV.

## 4. Main flows

### 4.1 Playback

1. `playVideo(file, startAt, list)` in `shell.js` resets speeds and prepares the queue.
2. `ensureQueue` chooses the queue:
   - with `list`: that list (from Recent or Explore);
   - without `list` and with `file.path`: the videos in the **same folder** (`L.folderOf`);
   - otherwise: the whole library.
3. `probeStream` checks that the proxy answers before opening the file; a failure is recorded.
4. `CodePlayer.play` sets the URL and starts. The `<video>` events update state, progress and notices.
5. `saveProgress` stores `{name, path, time, duration, updated}` every five seconds. When the video ends, the entry is removed.

### 4.2 Continue Watching and Recent

- **Continue Watching:** `L.continueList` returns in-progress entries sorted by `updated`. `renderHome` keeps **one entry per folder** (`L.folderOf(path)`).
- **Recent:** `remember(file)` adds the file to `recent` (maximum 30) with its path. Home shows only `video` items, in stored order (latest first). Choosing one plays it with that list as the queue.

**Why:** the "next" rule depends on where the user chose the video. Without the path the app cannot know the source folder.

### 4.3 Back

`back()` in `screens.js` and `handleFullBack(popped)` in `shell.js` resolve Back in this order:

1. Close the photo viewer.
2. Scroll the list to the top (`toTopOfList`), with focus on the first item.
3. Go up one folder level, or close the track panel, hide the controls and move to mini.
4. Return to the previous section or to Home.

**Why:** the remote sends Back as a key (461, 27 or 8), and the system may also produce a history event. A history `sentinel` and an "echo" counter prevent one press from doing two things.

### 4.4 Arrow navigation

`nav.js` finds, for each direction, the nearest visible link, with a penalty for misalignment. If none matches, focus stays. Panels (`data-modal`) confine focus inside them.

**Why:** on a TV, linear navigation (the next element in the DOM) does not match what the user sees.

If another layer has already handled OK (`defaultPrevented`), `nav.js` does not activate the link again. **Why:** a single press must not run two actions.

### 4.5 Speeds

- **Forward:** `playbackRate` with the values in `RATES` (0.5, 1, 1.5, 2, 5, 10). Outside 1x the audio is muted.
- **Rewind:** `CodePlayer.seekBy` once per second, stepping by the selected speed. The video stays paused.
- **Position guard:** `changeSpeed` compares the expected position with the actual one 1.5 s after a change. If it went backwards, it corrects the position and records the event.

**Why rewind is stepped:** browsers do not play backwards continuously. The position guard is a mitigation for a TV behavior that has not been confirmed yet (see `pruebas.md`).

### 4.6 Errors

Every failure goes through `CodeErrors.record(area, error)`:

1. `sanitize` removes tokens (`Bearer …`), the proxy's `s=` parameter and private keys.
2. `classify` returns the first matching rule: title, explanation and action.
3. The entry is stored at the top of the list (maximum 50). The same error repeated within 10 seconds is not duplicated.
4. Subscribers (the Settings indicator) are notified.

**Why:** a technical message without an action forces investigation. An explanation and an action let the user solve most problems alone.

## 5. Drive and authentication

- The TV signs an RS256 JWT with the service-account key (`src/auth/serviceAccount.js`) and exchanges it for an access token (valid for one hour). The token is reused until it expires.
- `driveClient.js` lists folders, children and media URLs; `escapeQuery` protects queries.
- `CodeDrive.crawl(kinds, onProgress)` walks the library level by level (breadth first), with a limit of 300 folders. **Why level by level:** folders close to the root appear first, and the limit stops very large trees.
- `thumbUrl` caches thumbnails for 20 minutes, because Drive URLs expire.

**Known risk:** the private key is part of the TV bundle (`app/js/service-account.js`, not versioned). This is acceptable only for personal use on the owner's TV. Do not distribute that file.

## 6. Proxy (`server/`)

`server/proxy.mjs` serves `/stream/<id>?s=<secret>` and `/subs/<id>`:

- It forwards `Range` to Drive with the `Authorization` header. The `<video>` element cannot send headers, and Drive rejects the token in the URL.
- If an mp4 has its index at the end, `faststart.mjs` remuxes it once (without re-encoding) and serves it from `server/cache/`. Limit: 10 GB; above that it answers 413 with a message.
- `subtitles.mjs` converts text tracks to WebVTT with ffmpeg.
- Streams are connected with `pipeTo`: if Drive cuts the connection midway, the response is closed and the process does not crash.

**Why a proxy:** the TV's `<video>` cannot send `Authorization`, and a token in the URL is rejected.

## 7. Build, packaging and tests

```bash
npm install
npm run build            # src/ -> app/js/app.js (classic script)
npm run check:es2015     # verifies the bundle uses no syntax newer than ES2015
npm run build:tv         # build + key in app/js/service-account.js
npm run package:tv       # + ares-package app -o dist
npm test                 # tests with node --test
```

Automated tests (`test/`) cover: logic (`logic`), player (`player`), Drive (`driveClient`, `driveCheck`), authentication (`deviceFlow`, `serviceAccount`), proxy (`proxy`), faststart and subtitles. Interface tests were run with headless Chromium during development and are recorded in `pruebas.md`; they are not in the repository because they depend on local test media.

## 8. Local storage

All keys use the `codetv.` prefix.

| Key | Contents | Written by |
|---|---|---|
| `settings` | Theme, font, text size, slideshow interval, sort, view, mini size and corner. | `screens.js`, `shell.js` |
| `progress` | `{id: {name, path, time, duration, updated}}` | `shell.js` (`saveProgress`) |
| `recent` | The last 30 opened files, with their path. | `screens.js` (`remember`) |
| `favs` | Favorite folders. | `screens.js` |
| `errors` | Error log (maximum 50). | `errors.js` |

"Log out" in Settings clears progress, recent items, favorites and settings. It does not clear the error log.

## 9. Decisions and reasons

| Decision | Reason |
|---|---|
| Browser JavaScript without frameworks | The TV's engine is old; a framework adds compatibility risk. |
| One `<video>` element | Avoids two audio sources and out-of-sync positions. |
| Local proxy for Drive | The `<video>` element cannot send authorization headers. |
| Queue scoped to the source folder | "Next" then matches what the user chose. |
| Recent items with their path | Shows each video's folder without querying Drive. |
| Chunked lists | Prevents blocking the TV with large libraries. |
| Error log with actions | Lets problems be solved without debugging. |
| Section switch (`flags.js`) | Disables features without deleting their code. |
| Stepped rewind | Browsers do not play backwards continuously. |

## 10. Limitations and open work

- The repository has no automated interface tests.
- `screens.js` and `shell.js` are large (over 900 lines each). Splitting them into per-screen modules is the recommended next step, backed by tests.
- Several behaviors depend on the real TV (see the use-case section of `pruebas.md`).
